# Occam's Razor (오컴의 면도날)

- **id:** occams-razor
- **분류:** 복잡도
- **정의:** 원래는 설명이 여럿일 때 가정이 적은 설명을 택하라는 원칙입니다. 화면 설계에는 유추해서 씁니다. 과업에서 같은 몫을 하는 안이 둘이면 요소가 적은 안을 먼저 시험합니다.
- **출처:** https://lawsofux.com/occams-razor/
- **읽은 범위:** 정의, 요점, 유래를 읽었습니다. 정의 문장은 2026-11-27에 새로 썼습니다. 원 연구는 읽지 않았습니다.
- **적용할 때:** 기능 추가 요청, 화면 요소 정리, 흐름 단축.
- **적용하지 않을 때:** 필수 기능까지 지워서 과업을 못 끝내게 되는 경우.
- **관찰 확인:** 요소 하나를 제거했을 때 과업 완료에 영향이 없는지 확인하고, 영향 없는 요소의 제거 목록을 기록합니다.
